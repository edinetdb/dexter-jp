# デモの録画手順（60 秒）

README の「10 分で動かす」と同じ手順を、そのまま画面に収めるための台本です。録画には鍵の要らない `bun run demo`（記録済みの実行の再生）を使います。何度撮っても同じ画面になり、鍵や会話の内容が映り込みません。

## 準備

- 新しいディレクトリに clone し直した状態から撮る（手元の `.dexter/` や `.env` を映さない）
- ターミナルは横 120 桁以上・縦 40 行以上。フォントは 16pt 前後
- シェルの履歴・プロンプトに個人名やパスが出る場合は、`PS1='$ '` などで短くしておく
- 録画は macOS なら `Cmd + Shift + 5`（画面収録）、ほかの OS は OS 標準の画面収録で構わない

## 台本

| 秒 | 画面 | 字幕（任意） |
|---|---|---|
| 0–8 | `git clone https://github.com/edinetdb/dexter-jp.git && cd dexter-jp` | 日本株の有価証券報告書に、仮説を当てるエージェント |
| 8–20 | `DEXTER_SKIP_BROWSER=1 bun install` | 依存を入れる（ブラウザは落とさない） |
| 20–25 | `bun run demo` | 鍵なし・通信なしの録画の再生 |
| 25–50 | 出力をゆっくりスクロールし、主張ごとの判定と、根拠の段落（書類種別・書類管理番号つき）を見せる | 会社自身が書いた段落に 1 本ずつ当てる。売買の判断はしない |
| 50–60 | 末尾の「検査した範囲」と「ここまで録画」の行で止める | 自分の仮説で回すには、EDINET DB と判定層の鍵、対応する LLM の設定が要る（Claude Agent SDK モードの `/check` はこの版では未対応） |

字幕には、画面に出ている判定・数字を言い換えずに使う。判定の意味（「裏付ける」「食い違う」「判定が割れている」）は README の「答え合わせ」の説明と同じ言葉にする。

## 撮った後の確認

- `.env`・鍵・メールアドレス・手元のパスが映っていない
- 画面の上部に「録画の再生」と出ている（実走と取り違えないため）
- 字幕に「おすすめ」「買い」「割安」など、売買や株価の水準を判断する言葉が入っていない
